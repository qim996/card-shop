# 卡铺 · 自动发卡网

一个可直接部署到 **GitHub Pages** 的简易发卡网：商品展示 → 支付宝付款 → 自动发卡密，界面简洁清爽。

- 纯前端静态实现（原生 HTML/CSS/JS，单文件自包含），无需服务器即可上线
- 内置 **演示支付模式**：不配置任何东西，开箱即可体验完整购买 → 发卡流程
- 支持 **网关支付模式**：对接支付宝当面付（配合可选的后端 `server.js`），真实收款
- 附带管理后台：商品 / 卡密 / 订单 / 支付设置

---

## 功能一览

| 模块 | 能力 |
|---|---|
| 商品页 | 商品卡片、价格、库存/已售、售罄自动置灰 |
| 购买流程 | 选数量 → 支付宝付款 → 支付成功自动发卡密 |
| 发卡结果 | 票据式结果卡，卡密一键复制 |
| 管理-商品 | 新增 / 编辑 / 删除商品，价格与描述 |
| 管理-卡密 | 批量粘贴导入卡密、库存明细、一键全复制 |
| 管理-订单 | 订单流水与发放记录 |
| 管理-设置 | 店铺名、公告、支付模式切换、网关地址、管理口令、数据导出/恢复 |

数据保存在浏览器 `localStorage`，管理页可一键导出 JSON 备份。

## 快速开始（演示模式，零配置）

1. 下载 `index.html`，用浏览器直接打开即可。
2. 首页点击任意商品 → 选择数量 → 点「支付宝支付」。
3. 弹出的是**演示收款码**，点「我已支付」即模拟付款成功并自动发卡。
4. 右上角「管理」进入后台（默认口令 `admin888`，可在设置中修改或留空）。

> 演示模式不真实扣款，用于体验完整流程和搭建店铺。

## 部署到 GitHub Pages

1. **新建仓库**：在 GitHub 上新建一个仓库（如 `card-shop`）。
2. **上传文件**：把 `index.html` 上传到仓库根目录（可连同 `README.md`）。
3. **开启 Pages**：
   - 仓库 → `Settings` → `Pages`
   - `Source` 选择 `Deploy from a branch` → 分支选 `main` → 目录 `/ (root)` → `Save`
4. 等待 1~2 分钟后，访问 `https://<你的用户名>.github.io/<仓库名>/` 即可。

> 之后每次推送新的 `index.html` 到 main 分支，页面会自动更新。

## 对接支付宝（真实收款）

### 原理说明

GitHub Pages 是纯静态托管，**无法安全持有支付宝私钥**（私钥放前端等于公开）。因此真实收款需要一个小后端网关：前端负责展示，网关负责生成收款码和确认到账。

```
用户 ──> index.html(GitHub Pages) ──> server.js(支付宝网关) ──> 支付宝开放平台
                                            ▲                          │
                                            └──────── 查询到账 ◄───────┘
```

### 第一步：准备支付宝当面付

1. 注册支付宝开放平台账号，创建「网页/移动应用」并**签约当面付**（需企业或个体工商户资质）。
2. 在「应用详情 → 开发设置 → 接口加签方式」生成/配置密钥：
   - 记录 **AppID**
   - 生成**应用私钥**（RSA2，PKCS8 格式）
   - 上传公钥后，平台返回**支付宝公钥**

### 第二步：部署网关（任选其一）

本仓库的 `server.js` 是对应网关，部署到任意能跑 Node 的环境：

```bash
cd card-shop
npm init -y
npm install express alipay-sdk qrcode

# 配置环境变量后启动
ALIPAY_APP_ID=你的AppID \
ALIPAY_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----..." \
ALIPAY_PUBLIC_KEY="-----BEGIN PUBLIC KEY-----..." \
ALLOW_ORIGIN=https://你的用户名.github.io \
PORT=3000 \
node server.js
```

免费托管参考：Railway / Render / Fly.io 等（绑定 HTTPS 域名后把地址填进前端）。

> 密钥只存在于网关服务端环境变量中，绝不写入前端代码或提交到 GitHub 仓库。

### 第三步：前端切换到网关模式

1. 打开网站 → 右上角「管理」（口令默认 `admin888`）→ 设置。
2. 支付模式选择「网关模式」。
3. 填支付网关地址，如 `https://your-gateway.onrender.com`。
4. 保存后，购买流程会改为展示支付宝真实收款码，支付成功后自动发卡。

### 网关接口约定

| 接口 | 入参 | 返回 |
|---|---|---|
| `GET /api/create` | `orderNo` 订单号、`amount` 金额(元)、`subject` 商品名 | `{code:0, qrcode:<图片dataURL>, orderNo}` |
| `GET /api/query` | `orderNo` | `{code:0, paid:true/false}` |
| `POST /api/notify` | 支付宝异步通知 | `success` |

## 安全与边界说明（请务必阅读）

- 本项目为**静态托管 + 前端发卡**方案，卡密以明文/浏览器存储形式保存在 `localStorage`，适用于**小额、自用、内部或演示**场景。
- **不适用场景**：高价值卡密、需要防爬/防刷、需服务端强制唯一性校验。这类场景应把卡密库放到后端（如网关 `server.js` 中），由服务端发卡并做幂等与去重。
- 纯静态页面无法阻止技术用户查看浏览器存储，请勿把高价值卡密直接放前端。
- 管理口令默认 `admin888`，上线前请在设置中修改或清空（仅作轻量防护，非安全机制）。
- 支付需如实核对金额；网关模式以服务端 `paid` 状态为准，前端轮询仅为展示。

## 常见问题

**Q：GitHub Pages 能直接收支付宝钱吗？**
不能。纯静态页面无法持有私钥做验签，必须搭配后端网关（本项目已提供 `server.js`）。

**Q：不想折腾后端，能用吗？**
能。演示模式完整可玩，适合先搭建店铺、跑通流程；个人小额售卖可搭配网关，或改用支付页跳转方案。

**Q：数据会丢吗？**
数据在浏览器 localStorage，换浏览器/清缓存会丢。请在管理页「设置」中定期导出 JSON 备份。

**Q：想自定义样式？**
所有颜色在 `index.html` 顶部的 `:root` CSS 变量中定义（主色 `--primary` 等），改一处即可换主题。
